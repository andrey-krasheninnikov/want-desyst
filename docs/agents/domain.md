# Domain docs

This repository uses one domain context covering shared foundations,
brand resources, framework UI kits and product themes.

Read root `GLOSSARY.md` and relevant ADRs in `docs/adr/`
before working in their area.

Proceed when these files are absent. Create them only when
terms or decisions need recording.

Use glossary terms consistently. Identify conflicts with existing ADRs
before proposing a different decision.
